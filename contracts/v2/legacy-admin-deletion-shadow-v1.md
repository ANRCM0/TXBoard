# Legacy Admin account deletion evidence v1

Status: Current isolated slice. Covers only the existing `AdminAccountProtection::deleteUnused` transaction. Historical deletions, trusted plugins, cascades and other writers are not reconstructed.

Strict default-off `LEGACY_ADMIN_DELETION_SHADOW_ENABLED` requires the existing local/testing isolated capture context. Native User lock, current Admin path/role, self protection and account-in-use checks remain authoritative. The native parent-account reference check now consults actual Schema: current migrations have no User parent_id; when an existing database has that optional column, its linked-child protection remains enforced. All mandatory native history checks still run. After native eligibility passes and before the trusted destroy hook, begin records the actual nonsecret persistent admission snapshot and current Admin reference. Session deletion, native Eloquent delete and its events retain their order. Append checks actual User absence in the same transaction after the native delete; a cancelled model delete that leaves the User present produces no deletion evidence and retains native response/session semantics.

One immutable `tx_legacy_user_deletion_shadow` row records `admin.user.delete`, version, actor, context, canonical 15-field admission snapshot, hashes, confirmation timestamp and `deletion_confirmed=true`. User deletion, session removal and successful evidence insertion commit or roll back together. The snapshot is the admission endpoint: trusted before/deleting hooks may change state afterwards. It does not attest to the last pre-DELETE state or absence of intermediate effects. No fake after snapshot, mutation event, financial journal, grant revocation, subscription transition or mapping mutation is manufactured. Legacy history has no User foreign key and remains stored.

Disabled capture performs no evidence SQL or context validation. Native missing/repeated User returns404; account-in-use checks can refuse before capture is consulted. No new idempotency or automatic retry is added. Fixed-safe capture errors cover malformed context/tickets and unavailable evidence storage. Trusted hooks, external effects and after-commit Node sync are not SQL rollback guarantees.

`core:admin-deletion-shadow-verify --user=<id> --isolated-copy` uses its own fresh transaction and bounded SELECT-only reads. It validates the closed admission snapshot and record/context/hash association, then reports whether the current User is absent. Reappearance is explicit; hash consistency is not a signature or independent historical proof. Complete mutation-chain coverage, actual Node/Provider revocation and migration readiness remain false. The additive migration retains data on replay and refuses populated down.

Acceptance requires native authorization/history protection, cancelled delete and hook timing, actual SQL rollback of User/sessions/evidence, immutable replay/down guards, read-only checks, and real independent MySQL session visibility. No production migration gate is opened.

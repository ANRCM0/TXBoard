# Native 开发基线与 CI 分工

更新：2026-10-16，依据用户在 C2 合并后的最新决定。

## 开发基线

项目仍处于开发阶段，尚未接入正式测试。本轮以已合并的 native C2 为业务基线，不再承担旧部署、旧数据库、旧协议或第三方旧包的过渡兼容交付。此决定覆盖早期 B0—B8 文档及开发约束中的兼容窗口、双轨迁移和旧站回填前置要求。

- Core 是账户、订阅、权限、订单与用量的唯一业务权威。Provider 管理代理凭据，Node 执行授权和计量，Gateway 适配当前接口；不为旧版本再建立第二套业务规则。
- 允许破坏性修改开发中的表结构、API、配置和包格式。修改时同时更新当前真实生产者、消费者、契约及直接相关检查，不新增只为维持历史格式的适配层。
- legacy、shadow 等残余实现仅表示代码尚在，不是未来必须支持的产品模式。隔离 Internal API 已退役；其余按关联功能清理，不再为它们补功能、扩展矩阵或要求先完成迁移才能继续 C3—C5。
- 可明确重建可丢弃的开发数据库和夹具。此约定不授权运行时自动删除数据，也不把不可逆业务写入伪装成可安全回滚。
- 权限、资源归属、秘密隔离、SQL 事务、幂等、计量准确性、持久回执和故障恢复仍是当前架构的正确性要求。
- C2 的免费购买和受限协议范围保持真实。C3 资金、C4 正式接口/生产凭据生命周期、C5 安装发布仍需实现，不因取消兼容要求提前开放。

新管理/用户前端继续延期至 TX-F，安装器仍由 TXBoard-Deploy 负责。保留的 Web、Theme、Plugin 是当前仓内实现；清理时处理实际引用，不要求维持外部旧版本兼容，也不借本批重新开发前端。

## 自动 CI 的唯一职责

| 所有者 | 日常职责 |
| --- | --- |
| `ci-api.yml` | 当前 PHP 默认测试集、语法、真实路由与 Schema/权限契约审计 |
| `ci-mysql.yml` | 当前 native 初始化、事务、唯一性与并发验证；相关 Provider/用量归属专项合并执行 |
| `ci-node.yml` | Go race、依赖与 vet、Node/Provider CLI、当前镜像命令和能力 |
| `ci-native-c2.yml` | 一条真实 native 激活、队列履约、Provider、渲染、流量、轮换和原周期结算闭环 |
| `ci-gateway.yml` | 当前 Gateway/SDK、Redis 安全与其独立镜像 |
| `ci-web.yml` | 现存 Web 源码变化时的类型、测试与构建 |
| `docker-txboard.yml` | Core 镜像、Compose、运行时依赖及启动/健康实物检查；正式标签另做发布资格检查 |
| `docs.yml` | 文档引用及 CI 策略静态检查，不启动业务环境 |

自动工作流保持 8 条。前五批已移除影子捕获、authority 和 Internal API 原型专属流程；接续三批再删除 9 条孤立 Usage/旧 Node 运行器，当前保留 11 条工作流，其中 3 条为显式手动 Provider 工具。Node/Web 日常验收支持叠加 PR。当前 PHP/MySQL 权限与事务、Node 共享组件 race 及 C2 原生真实闭环继续自动验证；不以过去 User 字段模型的结果宣称当前完整 Machine/WS/Xray 矩阵已验收。

同一批次内不再由 Provider 切片、C2、API 和 Docker 各自重复一遍相同 PHP/Go 测试。日常 PR 不执行十轮随机稳定性测试和旧站升级恢复矩阵；这些保留为显式手动或正式发布专项。镜像测试与源码测试验证的对象不同，不视为重复。

默认 `api/phpunit.xml` 已无历史目录排除，覆盖当前业务、共享实现和安全边界。InternalReadOnly 运行器及专属测试退役后，重复的 `phpunit-historical.xml` 与默认配置语义完全一致，因此一并删除；手动工具使用同一个配置并显式选择测试路径或 filter，不能借配置别名再跑一次默认全量。native 生命周期、权限与用量回归保留。历史证据保留便于查证，不将过去原型结果冒充当前 native 验收。清理范围、领域归属与剩余项见 [Core 清理](core-cleanup.md)。

`python scripts/check-ci-policy.py` 静态检查工作流 YAML、自动/手动归属、任务依赖和 PHP 测试选择，阻止历史矩阵意外重新成为自动门禁。新增正式业务时应更新实际组件的检查范围；C3/C4 的当前测试不能一直归入历史目录。

所有重型测试、构建、数据库和真实服务/流量联调在 CI 执行；本地只做语法、格式、差异与必要静态检查，不重建已删除的大型 Linux 环境。只复测改动直接影响的部分，不为记录 CI 结果增加无意义提交。

## 发布与结果

开发基线不等于正式发布。PR 仍需相关检查和审阅，实际已配置的远端规则照常执行；不伪造通过状态或绕过合并保护。重组旧 CI 是本次明确授权的配置变更，不再将过渡迁移专项当作开发门禁。若远端 required contexts 引用被重组的旧任务，应同步调整真实设置，不能用同名空任务冒充验收。

默认分支的 dev 镜像与正式版本分开记录。正式标签的资格、实物检查、版本来源和发布权限不能通过日常任务的 intentional skip 自动放行。

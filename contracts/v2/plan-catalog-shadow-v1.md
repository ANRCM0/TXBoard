# Plan Catalog Shadow v1

> Status: B1 catalog shadow implementation. Legacy Plan and OrderService remain authoritative. This command is limited to an explicitly isolated copy; it does not publish offers to users.

`core:catalog-shadow --isolated-copy --run=<key> --limit=<1..1000> --billing-timezone=<IANA> --currency=<code>` processes a bounded cursor below a frozen legacy Plan high-water ID. `--retry-plan=<id>` independently captures a changed or previously failed plan. Currency and billing timezone are explicit, with no invented defaults. Supported ISO 4217 currencies are USD, CNY, EUR, GBP, HKD, SGD, CAD, AUD, NZD and TWD, all with two minor digits. Other currencies are rejected until their legacy unit semantics have been confirmed.

| Table | Behavior |
| --- | --- |
| `tx_plan_revision` | Immutable current-catalog snapshot; unique `(plan_id,revision_no)` and `(id,plan_id)`. Records schema version, quota bytes, group/speed/device terms, resolved reset policy, explicit billing timezone, nonsecret source snapshot, content hash and capture timestamp. The legacy Plan ID is a logical reference; it does not restrict legacy deletion. |
| `tx_plan_offer` | Immutable current quote; unique `(plan_id,offer_code,version_no)`. Composite revision/plan foreign key prevents cross-plan ownership. Stores ISO currency, signed bigint minor amount, calendar months or explicit perpetual/reset kind, and frozen legacy calendar policy. No current Plan value is treated as historical User Terms. |
| `tx_plan_offer_availability` | Mutable, separate projection of legacy show/sell/renew and capacity limit; status shadow/superseded. Every offer remains a shadow. These flags neither authorize purchases nor replace PlanService's user-specific checks. |
| `tx_plan_catalog_shadow` | One current revision pointer per legacy Plan; original run key, source hash and row version. Changed immutable source appends a revision and offers, supersedes the prior availability, and atomically changes the pointer. Availability-only changes update the separate projection. |
| `tx_plan_catalog_checkpoint` | Frozen run context and high-water ID, bounded cursor, processed count and phase processing/complete. Completion of scanning is distinct from resolution of migration exceptions. |
| `tx_plan_catalog_exception` | Per-plan unresolved/resolved error evidence, attempt count and original timestamps; allows independent retry without erasing prior failures. |

All new-table foreign keys restrict deletion. The migration supports additive replay and refuses destructive rollback after any shadow data or checkpoint exists. It does not add foreign keys to legacy User/Plan, and does not enable `SubscriptionTerms.plan_revision_id` references.

Quota conversion uses the actual existing OrderService grant rule: Plan GiB multiplied by 1073741824 exactly once, with integer overflow rejection. Null legacy quota is retained as unknown, not changed to unlimited; zero remains zero. User-specific custom quota continues to come from the subscription shadow, independently of this catalog.

Prices are read from their original JSON decimal tokens, including quoted decimals, without passing raw database decimals through a PHP float. A float supplied to the conversion helper is first rendered as its round-trip JSON decimal string. Exact decimal arithmetic converts major units to minor units; nonzero precision beyond two decimal places, negative/nonfinite values and bigint overflow are rejected. The result must also equal the actual existing `(int) round((float) price * 100)` OrderService quote. A mismatch is recorded as a migration exception; no existing price is changed or silently rounded.

Calendar offers preserve existing `OrderService::STR_TO_TIME` month counts and Carbon `addMonths` overflow behavior. The installed Carbon implementation defaults `createFromTimestamp` to UTC, which is frozen separately from the explicit reset billing timezone. No 30/365-day duration is substituted. Perpetual and traffic-reset offers have no fabricated calendar duration. Capture timestamps are evidence of the current catalog, not historical contract dates.

Canonical content hashes exclude wall-clock capture times and mutable availability. Identical snapshots reuse the current revision; changed snapshots append new history. Interrupted transactions roll back the entire plan aggregate and leave retryable exception evidence. See [Core model](../../docs/architecture/v2/core-domain-model.md) and [Subscription shadow](subscription-shadow-v1.md) for remaining authority and production migration gates.

Verification on 2026-10-12: `PlanCatalogShadowTest` passed 23 cases with 108 assertions on SQLite, with two engine-specific cases skipped. MariaDB 11.4.12 passed all 25 cases with 119 assertions, including two independent-session tests that establish a stale REPEATABLE READ snapshot before another session commits a revision. Locking current reads preserve the committed revision, offers and next revision number. The group also covers exact decimal source handling, legacy quote/calendar parity, bounded restart, append-only history, independent availability, aggregate rollback, restrictive composite foreign keys, schema replay and unchanged custom User Terms. MariaDB used the dedicated local `txboard_concurrency_test` database. A production data copy, production migration and authority cutover have not been verified by this catalog slice.

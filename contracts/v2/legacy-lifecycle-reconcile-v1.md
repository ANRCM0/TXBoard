# Legacy lifecycle shadow reconciliation v1

> Retired on 2026-10-16: this isolated shadow/prototype runtime, commands and dedicated tests have been removed. The text below is historical evidence, not an available interface or an implementation requirement. Existing database migrations and records are retained; this cleanup does not run data deletion.

Status: Current isolated read-only slice.

`LEGACY_LIFECYCLE_RECONCILE_ENABLED=true` requires the existing strict local/testing isolated capture context. The new bounded CLI `core:lifecycle-shadow-reconcile --run=<subscription-backfill-run> --limit=100 --after-id=0 --isolated-copy` freezes its range at that existing checkpoint high-water. Its ordered union includes current Users, legacy subscription maps/exceptions, initial creation anchors, deletion anchors and capture streams; records beyond high-water are explicitly reported. No table or historical record is written. The CLI rejects outer transactions, invalid bounds and missing checkpoints, and emits no source values, credentials or snapshots.

Each selected User is locked first, then canonical creation/deletion evidence and at most the first mutation event are checked in the same transaction. Closed source policies accept Admin create, User registration and installer Admin bootstrap at their existing versions. Exact canonical snapshot/context/content hashes and ownership are validated; MySQL JSON member reordering preserves the same association. A mismatching current capture context, missing storage or corrupt evidence blocks the page rather than silently treating it as absent.

Present accounts classify as `source_present`; absent accounts with valid Admin deletion evidence classify as `known_admin_deletion`, and absent accounts without that evidence as `source_missing_unknown`. Valid deletion evidence with a present User reports `source_reappeared`. Initial creation evidence stays separate from deletion admission evidence. Current-source change and first-mutation-before association are observations, not a claim that the full mutation chain or creation-to-deletion history has been verified. Creation later than deletion is inconsistent. Hash consistency is not a signature or independent historical proof.

Mapping identity, referenced subscription ownership/status and occupied slot are reported as bounded associations. Missing source remains blocking even with known deletion evidence, including when its shadow subscription is still active. No subscription is released, cancelled or accepted as reconciled because a deletion anchor exists. Mapping absence, dangling ownership and unresolved exceptions remain explicit blockers. Creation evidence may be absent for older accounts without inventing an initial state; global coverage remains false.

When this independent flag is enabled, the existing subscription reconciliation attaches the same lifecycle observations for its existing page IDs and adds lifecycle inconsistencies to its differences. Its original high-water, source-missing and projection checks remain unchanged. This supplementary attachment does not replace the standalone union scan, whose range also includes orphan lifecycle anchors. Disabled mode performs no lifecycle evidence queries and keeps the original response shape.

Every result retains `mutation_chain_verified=false`, `global_coverage_complete=false`, `projection_applied=false`, and `migration_gate_open=false`. `page_consistent` describes only the bounded local observations. It cannot prove all pages came from one snapshot, complete writer capture, external revocation or production migration readiness.

The mapping checkpoint and capture run are different identifiers: billing timezone and currency must match exactly, while their independent run keys need not match. The closed checkpoint mapping version is verified before association. Every page ID list is canonical, strictly increasing and unique. `page_consistent` covers only lifecycle evidence and bounded mapping ID/state/ownership association; `projection_verified=false` explicitly excludes source hashes, Terms, period, subject and full slot-policy comparison. The original subscription reconciliation retains those complete projection comparisons.

A validated first event with a before-hash different from the creation anchor explicitly blocks lifecycle consistency as `LIFECYCLE_INITIAL_MUTATION_MISMATCH`; a missing or corrupt first event is refused by the existing capture validator. Matching that first event still leaves the remainder of the mutation chain unverified. Source changes across pages remain visible and cannot update an earlier anchor; complete pagination is not a cross-page stable snapshot.

Current-source mismatch with an initial anchor adds `LIFECYCLE_INITIAL_SOURCE_CHANGED` and makes this standalone page inconsistent even when a valid first mutation explains the beginning. Resolving a full chain or its applied projection remains outside this reader.

The range union is a bounded pagination observation. Per-object User, anchors, map/subscription/slot and unresolved exception use locking current reads, so an exception committed after the range snapshot is not hidden by an earlier REPEATABLE READ view. A real independent-session fixture commits that exception after the union query and confirms it blocks the page.

All four mapping references and any observed subscription/occupied-slot references must be canonical positive integer strings (or native SQL integers) no greater than signed INT64_MAX; zero, negative, fractional, leading-zero and overflow values are refused as `LIFECYCLE_MAPPING_INVALID`. Subscription identity and owner plus occupied slot identity must agree with the selected map/User. This is identity association only, without loading or certifying the referenced Terms/period/subject projection. Recomputed hashes never waive the canonical closed snapshot or self-actor policy checks.

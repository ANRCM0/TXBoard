## 必须关闭的完成缺口

### 1. 付费升级折抵

当前 native 购买没有不可变来源绑定的余值报价、明确折算规则和单次消费 claim。不能把全价替换当作升级折抵已实现。真实 activated runtime 对有历史付费条款或新报价非零的套餐替换明确拒绝；仅免费到免费保留既有规则。

关闭条件：冻结来源 Terms/原收款与报价时点、币种/折算/有效期，锁定当前订阅版本，保证同一余值只能消费一次；付款、取消、迟到成功、退款与来源消费在同一权威模型中解释，并通过针对性竞态。拒绝保护只防止错误计费，不代表功能完成。

### 2. 已履约历史权益的精准全退

候选自动全退只允许尚未履约或当前新购可安全撤销的情况。已履约续费、换套餐、流量重置以及已被后继条款取代的新购不能通过撤销整个订阅处理；这会错误抹掉以前购买或之后生效的权益。因此这些情况明确拒绝累计全退，不伪造成功。

关闭条件：按不可变原条款和消费历史定义恢复/结束策略，保留旧 UsagePeriod、未决批次与历史收款，准确处理后继购买，并验证退款与履约/用量并发。部分退款保留权益。原路退款执行是另一项明确未实现的渠道能力，目前只有退款至钱包。

### 3. 支付插件版本交接

永久 pin 保留原交易解释能力：已产生任意 dispatch 的插件不能破坏性升级、上传替换或卸载；停用仍可原交易验证/查询。包版本从已加载代码声明，必须与 manifest/数据库/冻结版本一致，以拒绝 Octane 驻留旧类冒充新包。

关闭条件：实现并验证旧版本代码保留及有界恢复路由，或可证明等价的明确版本化依赖交接；不能以终态、超时或禁用直接删除历史 verifier。当前保守策略安全但明显限制日常维护，不应称插件生命周期成熟。

### 4. 正式接口覆盖和安全通道

当前服务 registry 仅提供已列出的固定操作，不自动开放所有 Laravel 管理路由，也不新增管理员浏览器通道。账户/网络管理的完整写操作、完整嵌套输出 schema 仍需按真实消费者补齐；普通浏览器旧 `plan_id/period` 不能冒充 native `offer_id`。

生产反向代理必须验证实际客户端证书、清除用户伪造的验证头，保护到 Core 的下游 TLS，并验证 SAN/EKU/撤销与轮换。ingress 预算在 SQL audit 前按真实 socket 来源限流，生产需共享原子缓存与边缘 ACL。当前测试不构成这些实物部署的验收证据。

边界审计已有 service/epoch/actor/operation/domain/request/execution/status/time；拒绝、未知结果与成功分开。安全 resource target、risk/protocol 与 domain receipt-key 关联尚未全部收口。全局安装/包加载/body-size 拒绝、路由不匹配和 ingress 429 在逐条服务操作审计之外，不能说所有 HTTP 拒绝都已有 SQL audit。

### 5. 本候选集成验收与基础交付

本地只有轻量差异/语法/静态工具检查；没有 PHP/vendor/node_modules，不安装依赖或搭建本地数据库补跑。资金/授权行为、MySQL 竞态、真实 TLS 客户端、完整类型检查/构建由既有 GitHub Actions 集中运行。

关闭条件：候选提交和 stacked PR 的实际相关检查通过、修复发现、非作者领域审阅和依赖就绪；随后完成 C5 新安装/正常更新/必要恢复。检查未触发、跳过或只在旧提交通过都不能算当前验收。CI 成功也不自动授权合并或发布。

## 本轮检查与后续顺序

本轮已完成轻量 Core boundary、CI policy、native-only source guard 和 route auditor 单元检查。PHP/数据库/真实 TLS/完整 Gateway 测试尚未本地执行；后续 CI 状态以候选 PR 和精确提交为准，不在这里预填通过。

1. 冻结当前相关实现，集中运行候选 CI，先修复集成问题。
2. 补齐升级折抵与精准退款，再关闭支付插件版本交接限制。
3. 根据真实消费者补齐 C4 管理能力、审计/输出规范及真实信任轮换。
4. 在上述基础上进入 C5，交付可重复安装、更新、恢复和版本说明。

新前端、旧站迁移、完整协议/平台矩阵、HA、营销/复杂佣金不作为本轮假完成项；是否新增范围由独立需求决定。

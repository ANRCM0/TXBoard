# Native observed authorization-period metering v1 (Candidate)

This additive native contract attributes bytes to the User authorization period observed by the Node, identified by the existing monotonically incremented reset_count. It is not a wall-clock assertion for an offline Node and does not replace finite offline authorization leases or Usage-v2 Terms.

Core supplies a deterministic opaque traffic_period string on each native desired User. Its signed contents bind user ID and reset_count to a dedicated HMAC domain under the current application key. Node only transports tokens; it cannot mint future periods. Token verification is constant-time and checks canonical syntax, positive user ID, nonnegative bounded epoch, matching UID and no future epoch relative to locked User state. Application-key rotation requires separately preserving/reconciling old unacknowledged signed traffic and cannot silently discard it.

Ordinary native Node binds the current period to the meter owner before admission. On a changed period for a current User it closes the old runtime, samples its final counters under the old binding, then reconstructs under the new period. Hot updates without period change preserve the meter. Already sampled unreported bytes keep their original binding through snapshot changes, failed reports, durable pending and terminal spool, restart and authenticated replay.

Each nonempty period-aware report carries the existing aggregated traffic and traffic_segments entries with user_id, period, upload and download. Canonical segment ordering is by UID then token; duplicate entries merge only under identical UID/token. Every raw aggregate equals the exact sum of its segments, within existing integer and body limits. Missing/partial/unknown/malformed segments are rejected before acceptance. Legacy on-disk batches without this field retain arrival-period semantics and are explicitly reported as such; they are never relabelled with the current token during replay.

Durable receipt identity includes canonical segments as well as aggregated raw bytes. First accepted rate/day and normalized settlement input stay immutable. Traffic hooks that alter raw user/byte attribution incompatibly with signed segments are rejected visibly rather than guessed. The existing TrafficBatchJob keeps its original atomic ledger/server/user/stat transaction. Under the same sorted User locks, each segment increments a unique (user_id,reset_count) period usage record with raw and billed directions. Current epoch increments current User u/d; an older epoch increments historical usage/stat/server only and cannot consume a new cycle's quota. Per-direction billed values use the existing rate/floor rule and explicitly documented segment rounding. Rollback includes period rows, existing ledger and all counters. Exact replay never settles twice.

Acceptance must exercise a real native Node, actual VLESS/VMess bytes, an actual registered admin reset, queue delay and lost ACK; pre-reset bytes replay into the old observed period while current counters remain unchanged, then fresh authorized bytes charge the current period. Initial imported counters and older v1 traffic are not reconstructed into historical records. All protocols, offline wall-clock cutoff, production key recovery, HA and global migration authority remain separately bounded.

If unsaved legacy counters coexist with signed counters, Node emits separate FIFO batches: legacy bytes keep the old arrival semantics without attribution; later signed bytes carry complete segments. It never emits an empty period token inside an attributed report or silently assigns a new token to old bytes. A native restart authenticates and drains any existing immutable pending/terminal slots before admission.

Signed normal batches are bounded by both 10,000 segments and a conservative 512 KiB traffic JSON budget within the native 1 MiB request limit. Terminal capture drains every remaining bounded chunk, each with an independent original batch ID, into one immutable `RecoveryTail` bundle alongside the original pending slot. The bundle is limited to 4,096 chunks and 64 MiB encoded size; storage/capacity failure returns a visible error and restores original attribution, never claims durable completion. Partial ACK advances only the current process; the original file remains byte-identical until every chunk is acknowledged. Restart replays any already acknowledged chunks with their original IDs, relying on Core durable deduplication. Old single-batch files remain readable.

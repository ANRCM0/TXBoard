# 基础功能优先级

2026-10-14，用户调整实施顺序：先完成 Core/Gateway/Node 的基础功能，优惠券等扩展后续开发。本顺序覆盖之前“工单后优先优惠券”的候选建议。已完成切片与历史验收记录继续有效；现有登录、订单、支付、工单等原生能力保留，工作重点是补齐新链路缺口，而非重新实现已有业务。

先完成最小闭环：安装启动 → 创建用户与套餐授权 → 节点注册和配置 → 客户端连接 → 用量回传与扣量 → 到期/封禁/撤销 → 重启后恢复。默认关闭、当前权限、数据对账与生产切换条件仍按既有契约执行。功能后移不意味着未覆盖的旧写入可以绕过停止/排空门禁；全局迁移切换继续等待完整生产者证据。

| 顺序 | 优先级 | 任务 | 可验收结果 |
| --- | --- | --- | --- |
| 1 | P0 | Core 基础账户与套餐/订阅：认证、角色、用户状态、套餐授权、到期/封禁、基础配置；已有路径补齐归属和状态一致性 | 用户/管理员/Node 权限分开；授权、到期和封禁能沿真实链路生效；已有业务回归通过 |
| 2 | P0 | 节点管理与控制：Node/Machine/Group/Route 基础管理、节点注册与鉴权、配置分发、心跳/状态、断线重连 | 在真实 Core/Node 进程中添加节点、同步用户配置、连接客户端、变更配置并观察节点应用；SQL与提交后控制效果分别有证据 |
| 3 | P0 | 流量与配额闭环：真实计量、持久回传、去重、订阅归属、扣量、周期重置和断网补报 | 重放不重复扣量，重启不丢已确认记录，套餐/周期归属可对账；协议覆盖和未知结果明确 |
| 4 | P0 | 基础凭据生命周期：发行与交付、有限租约、到期/封禁/撤销、Node断线后收敛 | 实际Node消费凭据并按当前授权停止；离线恢复不能复活已撤销权限；生产秘密隔离需通过对应门禁 |
| 5 | P1 | 安装器基础交付：三组件安装/配置、启停、固定版本更新、备份恢复 | TXBoard-Deploy完成单机真实组件闭环；安装/升级失败能识别和恢复，版本与镜像一致 |
| 6 | P1 | Gateway 与必要 Internal API：围绕前四项补齐用户/管理所需读写，Core重新授权 | 实际Gateway/Core mTLS消费链完成；当前权限和DTO一致；管理员入口正式启用仍须对应替代契约与通道门禁 |
| 7 | P1 | 正式安全与恢复：生产PKI、轮换/吊销、防重放、SC-v2业务接入、恢复后epoch/回执/撤销保护 | 身份与通道故障拒绝；跨进程恢复不重复业务或复活权限；完整验收前不切换生产权威 |
| 8 | P1 | 基础购买与支付：套餐购买、订单支付/开通/取消、充值及账务一致性；先整合现有业务 | 付款/履约/退款/余额重放和故障结果可核对；不同时新增促销或支付插件平台扩展 |
| 9 | P2 | 商业与运营扩展：优惠券、礼品卡、复杂佣金/提现规则、内容/模板等新增能力 | 在基础闭环和相关权限稳定后，按独立契约和切片开发 |
| 10 | P2 | 高级拓扑与扩展：Cluster/HA完整方案、插件平台扩大、额外集成及按实测需求优化 | 完成对应多实例、外部效果和恢复验收；不以单机测试替代集群证据 |

日志、健康检查、测试、CI、秘密保护、备份以及当前必需的权限校验贯穿每批，不能等到高级功能阶段再补。单机优先；Cluster、新插件功能及促销不阻断基础开发，但若现有生产者仍能写入，生产切换必须覆盖或独立停止/排空它们。

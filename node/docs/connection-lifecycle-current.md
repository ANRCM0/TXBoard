# sing-box tracked connection lifecycle

Status: Current. This B3.3 prerequisite makes the existing sing-box `ForceCloseUser` capability perform actual TCP and UDP session termination. It does not enable a v2 traffic collector, Provider authorization or lease enforcement. Default accounting continues through the existing v1 Tracker and reporter.

The router's ConnTracker registers the tracked wrapper, its authenticated UUID and runtime user ID for both TCP and UDP. `CloseUserConnections` closes the currently registered sessions for that UUID. It keeps other users' sessions running and leaves the identity authorized for future connections. Removing or reassigning an identity through the user-map update both rejects new sessions for the former identity and closes its registered sessions. The admission recheck and registry insertion share the same lock as map changes, including after device/speed callbacks.

Closers run outside the registry lock. Each wrapper closes the underlying transport once, cancels its local rate-limit waits, removes its connection reference and updates connection/IP counts. TCP blocked reads and UDP blocked packet reads exit when their transport closes. UUID selection uses the registered identity, including when two UUIDs temporarily share a runtime user ID. Unknown or removed identities cannot acquire an untracked session.

The per-user cumulative byte atomics and existing byte-direction callbacks are unchanged. Removed users' final cumulative counters remain readable by `GetUserTraffic`; the v1 Tracker observes the final delta and does not add the unchanged totals twice. This slice does not change reset detection, per-packet timing, kernel restart accounting or UDP zero-copy direction conventions.

Linux Go 1.26.3 verification ran `go test -race -count=1` and `go vet` for `internal/kernel/singbox`, `internal/tracker`, `internal/service` and `internal/kernellifecycle`: 103 main tests and 18 subtests passed, with no skips. Tests include real TCP pipe and loopback UDP I/O, per-user termination, unrelated-session survival, removal races, concurrent close cleanup, zero-copy rate-wait cancellation and retained counters flowing through the existing v1 Tracker. Evidence: [verification record](connection-lifecycle-verification.json).

The xray backend continues to advertise `ForceCloseUser=false`; this change does not supply its missing per-user established-session termination. Core manual Terms changes may be discovered after traffic has already crossed a boundary, so exact runtime usage still needs advance boundary/fence coordination or conservative quarantine. Signed Provider grants, durable handoff and finite-lease admission remain separate work.

# Legacy subscription link digest adapter v1

Status: Retired on 2026-10-16. Historical design and validation record only.

The native development baseline does not require a legacy-link migration or
shadow observation mode. Its domain classes, middleware, configuration,
backfill/reconcile commands and dedicated tests have been removed. Current
subscription requests do not attach link associations or read this evidence.
Historical database migrations and stored evidence are retained; this cleanup
does not delete or convert data. The remainder describes the retired experiment,
not an available runtime contract.

Existing Client still authenticates the actual native User.token using native query-token precedence/database equality; SubscriptionController retains availability and UUID-based protocol rendering. This adapter observes only that authenticated User and never authenticates a digest, authorizes a Subscription or returns a Provider credential. Missing/changed/damaged shadow evidence blocks the observation, while native URL/body/headers keep their current behavior. Native credential rotation invalidates the old link normally; this slice never rewrites/reissues URLs or adopts a changed token into an existing immutable link.

`LEGACY_SUBSCRIPTION_LINKS_ENABLED` must be strictly true and Core isolated-copy strictly true in local/testing. False performs no adapter SQL/key IO; ambiguous values are refused. The operator supplies an absolute, regular, non-symlink private key file (group/world access denied). The closed JSON file is `{version:"legacy-link-key/v1",key_id:<ASCII 1..64>,generation:<canonical positive decimal string <=2147483647>,key_hex:<64 lowercase hex>}`. The 32 random key bytes never enter SQL, exceptions, logs or DTOs. A domain-separated HMAC key-check binds metadata to key bytes, detecting silent replacement under the same ID/generation. There is no runtime key rotation or production key distribution mechanism in this slice.

Token digest bytes are HMAC-SHA256(key, ASCII `txboard.legacy-subscription-link.token/v1` || 0x00 || uint32-BE byte length || exact persisted token UTF-8 bytes). Length is1..4096 bytes; blank or invalid UTF-8 is refused. No trimming, case folding, Unicode normalization, hashing URL prefixes or converting bytes to numbers occurs. Native token collisions use a bounded column-to-column native User equality self-join, so native database collation ambiguity is refused even where digest bytes differ. The adapter selects persisted token only transiently under the User fence; new SQL bindings contain IDs and digests, never token/UUID/password/private URL bytes.

Context/source/content JSON canonical bytes recursively sort object keys by byte order and encode UTF-8 with JSON_UNESCAPED_SLASHES|JSON_UNESCAPED_UNICODE; every reference/generation/time in evidence is a canonical decimal string, and no floats occur. Link context is exactly `{version,key_id,generation,key_check}`. Checkpoint context additionally freezes `mapping_run` and `high_water_user_id`; its canonical hash binds the range, and reconcile checks the existing completed mapping checkpoint again. Source exactly `{version,legacy_user_id,subscription_id,map_id,token_digest}`. Their SHA256 hashes and immutable content hash preserve MySQL JSON key-order changes. Token digests and key-check hashes are neither Bearers nor historical proof/signatures.

Additive links have unique legacy User, Subscription, mapping reference and (key_id,generation,token_digest). User→map→one current Subscription association must be unique and verified; any second Subscription for the same User, wrong owner/map, unresolved mapping exception, unverified map or native token collision is refused. All associations are read under User-first current locks in ascending Subscription ID order. Cooperating User-first writers are fenced; arbitrary trusted hooks/plugins/SQL writers remain outside this proof. Existing source changes and database constraints do not imply global uniqueness guarantees across noncooperating concurrent writers.

`core:legacy-links-backfill --run=... --mapping-run=... --limit=100 --isolated-copy` freezes high-water at an existing completed Subscription backfill checkpoint. It maintains its own durable cursor/context, per-user savepoint and fixed-code exceptions. Replay matches immutable hashes and resolves only the same exception; conflicts never overwrite existing link evidence. `--retry-user` only targets an existing unresolved exception within that fixed high-water. Users created afterward are reported, not silently enrolled. Unmapped/missing/ambiguous accounts keep the run blocked. `core:legacy-links-reconcile` is bounded and SELECT-only, revalidates current raw token digest/context/owner/map/Subscription and surfaces source/key changes. No legacy User, subscription, slot, provider or business counter is written.

The optional after-Client observer attaches only a typed nonsecret association (IDs, key metadata and authorizes=false). After native availability, SubscriptionController validates that typed association belongs to the same native User before making it available to protocol/server rendering hooks. It never swaps the native credential source. Render output contains no extra link fields, headers or credentials. Request-local association failure cannot authorize or substitute another account.

All reports keep legacy authority, global_coverage_complete=false, projection_applied=false and migration_gate_open=false. Production key lifecycle, stable snapshot acceptance, audited rotation/invalidation, Provider import/grants and removal of plaintext legacy token compatibility remain separate gates. Existing UUID/URL secrecy and retention rules are unchanged.

Strict parsing rejects duplicate members in key files and returned raw context JSON. Database contexts use native JSON storage and canonical object semantics: Oracle MySQL normalizes identical duplicate members before reads, so their original lexical form is unavailable to the adapter. Such an unchanged normalized object must still match the exact closed context, source and content hashes; extra fields or changed values remain refused. Engines preserving duplicate bytes are refused on read. This is not proof of the pre-normalization SQL input or arbitrary trusted direct-SQL behavior.

Every key load refreshes filesystem metadata before regular-file, symlink, size and private-permission checks. Long-lived workers must reject a previously private file made public and may read it again only after a fresh private-permission check; a prior cached denial is not the current file state.

# Authority native writers and producer schedule v4

> Retired on 2026-10-16: the isolated authority migration prototype, CLI, configuration and dedicated tests/workflows have been removed. This document preserves historical protocol evidence only. Current installation admission and domain writes are described in [Core cleanup](../../docs/development/core-cleanup.md). Historical database rows and migrations are retained and cannot authorize native initialization.

Status: Current isolated implementation contract; verification is recorded separately. Default-off and legacy authority remain mandatory. This fourth fixed inventory extends v3 on the same singleton. No registered inventory is global writer coverage or global drain proof.

Fixed `extend-native --key=<id> --expected-epoch=3 --isolated-copy` exclusively changes legacy/v3/open3 to legacy/v4/open4; prepare from original expected4 commits prepared5. V1 prepared2, v2 prepared3 and v3 prepared4 stay unchanged and cannot extend/reopen. A new immutable native upgrade receipt binds the original finance receipt, prior v3 expanded state, fixed v4 writer/effect inventory and target state. All earlier hash recipes remain intact. Read-only recovery uses closed bounded probes; SQL/actions/scopes cannot be provided by rows or CLI.

The v4 scope/version is `native-sql-writers/v4` / `authority-writer-fence/v4`. Twenty-six root writers retain the sixteen v3 owners and add Plan flags/sort/delete, Admin order assign/commission-review, commission cron review/distribution, standalone traffic reset, schedule repair and legacy traffic fetch. Their original transactions admit authority first. Commission manual begin/commit and original fraction/duplicate-risk semantics remain; bulk review and default per-User fetch/schedule writes gain only an enabled isolated transaction bridge. Default-off business paths and callbacks retain original SQL behavior.

V4 admission returns an internal proof bound to actual PDO identity, PID and the actual pending outer Laravel DatabaseTransactionRecord object. PDO identity uses a weak reference; holding a proof cannot keep a disconnected or purged physical transaction open. A scoped registry indexes that object, without process-global or Redis flags. Every root admission and lookup removes proofs whose outer record is no longer pending, including older declared versions; a proof retains its own record, so WeakMap alone cannot release closed transactions in a long-lived worker. Nested reset/UserService/commission helper validates the existing proof; it never first-admits after Order/Code/User locks. Rollback and rebegin at equal numeric depth, savepoint rollback, retry3, fork, purge/disconnect, alternate connection and after-commit misuse are checked against actual transaction lifetime. Unknown outer transaction without proof refuses; transaction level alone is insufficient.

Only declared enabled v4 replaces UserObserver scheduling timing. Each actual created/updated/deleted event stages its own immutable nonsecret intent within the admitted SQL transaction, capturing its action, original group removal, whether schedule calculation is needed and a closed source hash. Multiple saves or successive transactions get different intent identities. Cancelled or rolled-back model operations do not leave committed intent history. The producer model's wasChanged/original attributes are not overwritten.

At actual TransactionCommitting, before PDO commit, a fixed handler validates the proof and processes each staged event. Schedule calculations use the original TrafficResetService with an independently read current User and suppressed events. If observer capture is explicitly enabled, the real ObserverSchedule event follows the original producer capture in the same transaction; existing creation and producer records are never rewritten. Separate delivery rows retain schedule application evidence. This intentionally moves schedule SQL from after-commit into the original producer transaction only for v4.

After commit, pending Node notification intents hand off through original NodeUserSyncJob with only the original fixed action/user/old-group fields. A queue enqueue ACK is `handed_off`, never Node delivery. A finite SQL lease and attempt token fence pending/unknown handoffs; failure or result loss stays unknown and a bounded fixed retry may enqueue duplicate original notifications. No exactly-once delivery or global drain is claimed. A fixed isolated CLI scans bounded pending/unknown/expired handoffs; rows contain no arbitrary endpoint or operation. Producer rollback/SIGKILL removes schedule and intents; commit/SIGKILL before notification retains recoverable pending work.

The migration adds only native upgrade receipt, immutable postcommit intent and separate mutable delivery tables. Replay preserves history; populated down refuses. Intents contain no email, UUID, token, password, URLs or raw request body. Trusted plugins, uncaptured autocommit writers, registration/auth/bootstrap/credential CLI, independent Node/Provider effects and unverified database connections remain outside global coverage. All global/target-authority/migration flags remain false.

Acceptance requires native HTTP/cron/fetch/reset behavior and default-off regressions, real proof lifetime misuse cases, exact capture chain sequence/endpoints, multi-save/per-transaction intent independence, original group notification preservation, independent MySQL authority wait/commit/rollback/SIGKILL, postcommit queue-loss recovery, unchanged old prepared histories, bounded safe CLI/storage checks and full API integration. Verification uses dedicated synthetic databases only.

Updated code gates newly bound root writers whenever authority fencing is enabled, so an older process declaration cannot bypass a published newer inventory via an old default branch. Their older stored inventories refuse those root operation names until explicit expansion. Existing older admitted financial outer transactions may inherit an object-bound proof for their original nested helpers; this does not adopt v4 schedule timing or add those helpers as standalone old-version owners. Default-off still takes the unchanged paths.

# Authority writer inventory expand v2

> Retired on 2026-10-16: the isolated authority migration prototype, CLI, configuration and dedicated tests/workflows have been removed. This document preserves historical protocol evidence only. Current installation admission and domain writes are described in [Core cleanup](../../docs/development/core-cleanup.md). Historical database rows and migrations are retained and cannot authorize native initialization.

Status: Current isolated slice isolated explicit inventory expansion. This is a reviewed seven-writer subset, not a global fence or production authority switch. Existing [authority v1](authority-writer-fence-v1.md) records and prepare receipt hashes remain readable without rewriting history.

The same `tx_authority_writer_fence.id=1` retains authority `legacy`. Fixed CLI `expand --key=<id> --expected-epoch=1 --isolated-copy` takes its exclusive lock, validates old scope/version/open epoch1 plus both closed receipt stores and atomically publishes `native-sql-writers/v2`, `authority-writer-fence/v2`, open epoch2 with fixed code inventory hash and one immutable upgrade receipt. It refuses old prepared epoch2 and never reopens it. New prepare accepts expected epoch2 and changes the same row to prepared epoch3, preserving the original prepare receipt table and version-specific request/hash semantics. Exact expand replay returns its original upgrade receipt; different key/epoch refuses. Lost expand output is diagnosed by fixed SELECT-only `recover-expand`; no recovery command changes state.

The closed inventory is `admin.user.create`, `admin.user.update`, `admin.user.delete`, `admin.user.credentials.rotate`, `admin.user.bulk-ban`, `admin.plan.save`, `traffic.batch.settle`. Process configuration declares worker scope, version, epoch and legacy role. The original three-key config is an explicit v1 declaration; five-key config must use an exact supported scope/version pair. Wrong scope/version, inventory or epoch refuses covered writes. Status, recover and recover-expand inspect stored scope/version independently of worker declaration, while retaining strict isolated/legacy context and canonical config values. Unknown config keys and ambiguous flags fail closed.

A nullable `inventory_hash` column is additive. V1 state hashing excludes that null column, so actual pre-expansion prepared rows and receipts retain exact old hashes. V2 state includes it and requires the fixed code hash. The upgrade receipt binds its key, both scope/version/epoch identities, original state timestamp/hash, expanded state hash, fixed inventory hash and preparation time; all closed fields are verified. Each receipt store is checked with a bounded maximum-two-row cardinality probe. Missing, incompatible or extra storage/evidence fails closed. Additive DDL replay preserves data; populated down refuses column or history removal.

All five added transaction owners acquire authority first within their existing business transaction: delete/rotate before User; bulk-ban before sorted Users; Plan save/force before Plan/selected Users; TrafficBatch before Server/batch dedupe/sorted Users. No new outer business transaction, generic SQL interceptor or late capture admission is introduced. Default-off keeps existing SQL paths with no authority reads. Plan flags/sort/delete, payment/order/wallet/gift, independent plugins and all other writers remain outside this inventory. Synchronous PlanObserver effects of covered saves share their producer transaction. A persisted Plan change without an outer transaction is explicitly refused by that observer when this isolated fence is enabled; no late admission is attempted. This observer check is not proof that unknown/plugin outer transactions were admitted.

UserObserver after-commit schedule/Node effects, caches and arbitrary hooks do not retain the producer SQL fence. Prepare between original commit and those effects remains a separate drain/recovery requirement. Legacy TrafficBatch duplicate identity and native retry3/Redis-after-commit semantics are retained; enabled prepared admission occurs before Server/dedupe so even a duplicate may be rejected while prepared. Worker error reporting uses fixed nonsecret authority failure text.

Results disclose the exact stored scope/version and its covered inventory, with `global_writer_coverage_complete=false`, `global_drain_complete=false`, `target_authority_active=false`, `migration_gate_open=false`. No install or frontend behavior changes. Acceptance requires real pre-v1 prepared history fixture with unchanged recovery hashes, native five-writer default-off/enabled/blocked behavior, expanded admission and exclusive prepare ordering on independent MySQL sessions, expansion/prepare rollback and SIGKILL recovery, exact replays, code-inventory/config/storage corruption checks, and full API regression. Hashes are consistency evidence, not signatures.

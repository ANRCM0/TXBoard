# Actual Service usage-v2 and Core HTTPS fixture

This fixture exercises the [isolated Service contract](../../../contracts/v2/node-usage/isolated-service-v2-v1.md).
It runs the real Service.Run loop with native TXBoard initial config/users/handshake,
production enforcing sing-box ConnTracker over memory TCP, native HTTPS Reporter,
MariaDB receipt/outbox and existing settlement worker. Kernel lifecycle is injected
only to route test memory TCP without a live proxy listener; separate Go tests cover
actual full sing-box listener startup and the attached prepared tracker.

It requires Linux, locked PHP/Go dependencies including Core autoload-dev fixtures,
Go race support, MariaDB client/server, Redis, OpenSSL and Python3. Only an empty
exclusive `txboard_service_usage_test` database and its single-database principal
`txboard_service_usage` at127.0.0.1 are accepted, with APP_ENV=testing and
DB_CONNECTION=mysql. The launcher never grants privileges or resets/destroys a DB;
external fixture setup must provide that isolated empty state. Existing populated
history is refused. Supply local test DB/Redis connection settings via environment.

```sh
python3 scripts/tests/node-service-usage/run.py /fixed/TXBoard/api /fixed/TXBoard/node /private/new-evidence
```

The runner migrates then builds the actual Service Go test binary with race before
seeding the unchanged finite Core grant. Cold compilation consumes no authorization
window. The exclusive synthetic User is force-filled with the existing fixture owner
id7 because the authoritative model guards mass-assigned IDs; the normal model is
not modified. Native users/config and the UsageRegistry grant therefore refer to the
same actual owner. Synthetic credentials never appear in public evidence.

Two ephemeral loopback PHP/TLS listeners expose only fixed native Node operations,
using a one-day certificate with127.0.0.1/localhost SAN and normal TLS1.3 trust.
There is no Admin/Internal mTLS credential. The fixture test binary runs explicit
capture/settled phases using TXBOARD_SERVICE_USAGE_DIR/ENDPOINT/PHASE generated by
this runner, and ordinary Go tests skip that opt-in case without those inputs.

Actual Service worker sends11-upload/7-download while native heartbeat/online reports
omit v1 Traffic. SQL pending ACK is independently checked before settlement. Core's
original3/2 floor gives16/10 billed, total26. A second Node invocation queries the
real settled receipt and resubmits original batch; SQL still has one batch/one
ledger entry, original raw totals and legacy User u/d0/0, proving no v1 double write.
The closed Service/journal/spool keep their original identity and receipt history.

Fresh evidence includes actual Session/submission, pending/settled receipts,
immutable mode journal/spool, SQL summaries, public cert and content hashes. Private
key.pem/test executable remain local0600 and are excluded from public export.
Do not treat metadata hashes as independent proof of hostile same-OS history.
The [verification report](../../../node/docs/service-usage-v2-verification.json)
records the exact frozen runtime/test sources, successful and preserved failed
snapshots, database backups/resets and limitations. Production Service handoff,
credential admission, source refresh, restore and global authority remain gated.

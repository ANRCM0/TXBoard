# Authority writer fence v1

> Retired on 2026-10-16: the isolated authority migration prototype, CLI, configuration and dedicated tests/workflows have been removed. This document preserves historical protocol evidence only. Current installation admission and domain writes are described in [Core cleanup](../../docs/development/core-cleanup.md). Historical database rows and migrations are retained and cannot authorize native initialization.

Status: Current isolated SQL writer-admission slice. Scope is only the existing native Admin UserEditorController create and update transactions. It is not a global migration fence, production cutover or new v2 business authority.

Strict default-off `AUTHORITY_WRITER_FENCE_ENABLED` retains native behavior with zero fence/context SQL when false. Enabled requires local/testing and the existing explicit isolated-copy marker. Worker authority role `legacy` and canonical positive INT64 epoch are process configuration, never an HTTP argument or a cached Redis assertion. The additive migration creates an initially empty singleton authority table plus immutable bounded prepare receipts; it does not initialize authority during DDL. Explicit isolated CLI init installs scope `admin-user-editor/v1`, legacy/open epoch1. The writer never initializes missing authority.

Inside the original create/update business transaction, before any actual target User lock or insert/update, admission reads singleton row1 with a current shared SQL lock and validates closed scope/version/authority, open phase and exact worker epoch. It retains that lock until the native transaction commits, rolls back or its connection dies. Native validation, permissions, hooks, capture and after-commit effects remain authoritative. The lock order is authority row -> native User -> existing capture dependencies. This adapter adds neither a second business transaction nor a generic SQL interceptor.

Prepare is a fixed local command with reviewed request key and expected epoch. It takes an exclusive current lock on the same authority row, waits all admitted create/update SQL transactions, then atomically advances epoch by one, changes only phase to prepared and inserts one immutable receipt. Prepared phase refuses new covered writes; stale worker epochs and wrong roles are refused. This change does not publish v2 authority, attest all workers drained, revoke credentials or cover trusted direct SQL/plugins, other User writers, payment callbacks or after-commit Node effects.

The fixed CLI supports only init, prepare, status and recover; no SQL, command, arbitrary scope, URL or file argument exists. Recover is a fresh bounded SELECT-only probe of the singleton and at most two receipt rows (the second is an explicit corruption/unknown-history guard). Committed prepare returns the same receipt on exact repeated key+expected epoch. Different input or another key after preparation is refused. Absent receipt with unchanged open epoch is inconclusive and permits the operator to retry that exact prepare; recovery never reopens writes or changes authority. An insert/commit failure rolls back epoch, phase and receipt together. A killed admitted SQL connection releases the lock and rolls back its transaction; a killed preparer before commit leaves no committed prepare, while committed prepare with lost output is recovered by retained receipt.

All results retain legacy authority, `covered_writers=[admin.user.create,admin.user.update]`, `global_writer_coverage_complete=false`, `global_drain_complete=false`, `target_authority_active=false`, and `migration_gate_open=false`. Evidence hashes check consistency, not externally signed history. Missing/corrupt authority or receipt storage fails closed with fixed safe errors. Additive replay preserves rows; down refuses populated authority/receipt tables.

Acceptance requires original native HTTP permission/default-off regressions and fixed CLI validation, shared admission/exclusive prepare ordering on real independent MySQL sessions, commit/rollback/SIGKILL paths, exact duplicate prepare and output-loss recovery, bounded SELECT-only status/recover and schema/history guards. Production PKI, cluster executor lease, all-writer coverage, actual v2 publication and production migration remain outside this slice.

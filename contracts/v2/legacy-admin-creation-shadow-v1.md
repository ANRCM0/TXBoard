# Legacy Admin account creation evidence v1

> Retired: 2026-10-16 native development cleanup removes this capture runtime, flags and verifier entry points. The text below records historical behavior only. Database migrations and existing evidence remain; current account writes do not emit this shadow evidence. See [Core cleanup](../../docs/development/core-cleanup.md).

Status: Current isolated slice. Only the existing native Admin account create transaction is covered. Registration, installer bootstrap, trusted PHP plugins and historical users remain outside this slice; no missing creation history is invented.

Independent strict default-off `LEGACY_ADMIN_CREATION_SHADOW_ENABLED` also requires the existing capture context, local/testing and `CORE_SHADOW_ISOLATED_COPY=true`. After native input, current Admin authorization, Plan and duplicate-email checks, begin freezes the current context and actual Admin User ID inside the original transaction. Append follows the actual User INSERT and precedes commit, reading the real persisted allowlist fields under that transaction. UserService defaults, GiB-to-byte conversion, password/UUID/token creation, response and after-commit Observer timing remain native.

One immutable `tx_legacy_user_creation_shadow` row per created User records `admin.user.create`, version, actual Admin reference, capture context and hashes, captured_at and the initial nonsecret snapshot. It contains exactly the existing 15 User mutation-capture fields, integer strings and bool banned. It never includes email, password, UUID, Token, invite/Telegram secrets or a manufactured before-state. No mutation event, wallet journal, Terms, live grant, mapping or high-water extension is created merely because a User was inserted. No legacy User foreign key is added, so later native deletion retains historical evidence.

Failure rolls back the native User insertion and evidence together. There is no new idempotency key: native duplicate email and non-idempotent create remain authoritative. Disabled capture performs no evidence SQL or context validation. Ambiguous flags, context drift, malformed fields or unavailable evidence storage refuse the isolated operation with the existing fixed-safe capture exception. Trusted hooks, queues and external effects are not SQL rollback guarantees. After-commit schedule recalculation may change the final endpoint; this must remain visible rather than overwrite the initial snapshot.

`core:admin-creation-shadow-verify --user=<id> --isolated-copy` performs bounded SELECT-only verification in its own fresh transaction, rejecting an outer snapshot. It validates closed canonical snapshot fields, immutable record/context/source hashes and reads the current User plus at most the first subsequent capture event. The first event's content and stream/context association are checked before comparing its before-state to the initial evidence. It reports source missing or changed explicitly. It does not certify the remaining event chain, global writer coverage, notification delivery or a migration gate. Full mutation-chain verification remains the separate existing command. Evidence is immutable; `down` refuses a populated table, additive DDL replay keeps history and rejects incompatible schema. Hash consistency is not a signature or an independent historical source.

Acceptance requires native permission/default-off regressions, exact persistent snapshot and secrets exclusion, insertion rollback on evidence failure, after-commit endpoint change visibility, compatible mutation anchoring, additive schema/down refusal, and real MySQL transaction verification. Production writers and full B1 remain gated.

The shared physical initial-evidence table may also retain separately versioned registration records. This Admin facade/verifier remains restricted to `admin.user.create`; its own flag, ticket shape, version and existing hashes stay unchanged. Registration uses its [separate isolated contract](legacy-registration-creation-shadow-v1.md) and verifier.

Core installer bootstrap records are likewise separately gated and versioned under the [bootstrap creation contract](legacy-bootstrap-creation-shadow-v1.md). The authenticated Admin facade never accepts a self-creation ticket or another source policy.

# Subscription Shadow v1

> Retired on 2026-10-16: this isolated shadow/prototype runtime, commands and dedicated tests have been removed. The text below is historical evidence, not an available interface or an implementation requirement. Existing database migrations and records are retained; this cleanup does not run data deletion.

> Status: B1 additive implementation. Legacy User/Plan/Order services remain authoritative. These records do not issue authorization or change public APIs.

The migration creates native `tx_*` shadow tables. Existing `tx_user` and `tx_plan` tables and their writers are unchanged. References to legacy users/plans are logical references: adding restrictive foreign keys to those tables would change existing deletion behavior. Reconciliation must detect missing sources. All foreign keys between new tables use RESTRICT; history is never cascaded away.

Byte values and database IDs serialize as decimal strings in the new models. UTC timestamps serialize as integers or null. Internal database IDs continue to be PHP integers. A quota of zero stays zero; null does not silently replace it. Monetary conversion, catalog revisions/offers, provider imports and runtime cutover are outside this slice.

`SubscriptionSlotService::reserve(int $userId, int $subscriptionId, ?int $now = null): Subscription`, `transition(int $userId, int $subscriptionId, string $status, ?int $now = null): Subscription` and `release(int $userId, int $subscriptionId, ?int $now = null): void` run within a transaction and lock User, then its persistent slot, then subscriptions in ascending ID order. Active and suspended unexpired subscriptions reserve a slot. Expiry is checked inside the lock, at the half-open boundary `expires_at <= now`. A live suspended subscription prevents a second activation. Releasing a still-live reservation is rejected. These services manage shadow records only and do not mutate legacy User fields.

Rollback drops empty shadow tables only. Once any shadow business/history/checkpoint row exists, `down()` refuses automatic destructive rollback and requires the documented backup/restore or forward-fix process.

Schema expansion is resumable after committed DDL: repeated `up()` checks declared column types, nullability, defaults, enum values, owner keys and restrictive foreign keys. Missing later tables or constraints are added without deleting existing records. Conflicting definitions stop the migration. SQLite foreign-key alterations preserve its enum CHECK constraints; they are restored when a prior SQLite rebuild removed them.

Verification on 2026-10-12: `SubscriptionSlotTest` passed 22 SQLite cases (50 assertions); its engine-specific concurrency case was skipped there. The complete group passed 23 cases (89 assertions) through Laravel's MySQL driver on MariaDB 11.4.12. In the concurrency case, 32 independent PHP processes opened separate database sessions from one barrier: exactly one activation succeeded, 31 received the occupied-slot error, and all losing status changes rolled back. These synthetic tests do not replace production-copy migration or cutover validation.

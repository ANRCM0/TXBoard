# 管理端原生模型映射与验收范围

日期：2026-10-21。用户已选择保留 TXBoard 原生业务模型，补齐对应页面和真实操作。此选择解决旧模型差异，不豁免原生页面缺少的交互。历史审查中的缺口以本表和[修复进度](admin-native-repair-progress.md)为后续判断依据。

| 参考能力 | 本轮原生实现与边界 | 功能验收覆盖（结果见修复进度） |
| --- | --- | --- |
| 节点排序/协议编辑 | 完整集合排序 CAS 与稳定锁；11 协议实际元数据、证书条件表单及 JSON 模板。Shadowsocks 不提供没有消费链的 client_fingerprint；Mieru 编辑原生编码字段 | Actions 排序并发、协议与浏览器用例 |
| 服务器概览/关联节点 | 全库连接与负载观测、当前页多选筛选、绑定/迁移/解绑/启停及预填创建。负载过期明确未知，写入复用节点配置修订 | 真实 Core、权限、原请求恢复和手机用例 |
| 用户更换套餐 | 在原生条款调整 owner 内选择不可变发布修订并追加证据；默认保留到期与重置规则，不产生新付款 | 见[改配语义](admin-entitlement-plan-amendment.md)，MySQL 与 gateway 用例 |
| 手工标记付款/分配订单 | 使用原生关闭、重试及付款/分配证据，不提供绕过支付与账本的状态覆盖 | 原生订单任务用例 |
| 用户邀请人/手机/角色 | 展示原生邀请关系；不可变关系不任意重写。无手机号验证所有者时不添加任意手机号；角色授予与普通资料分别授权 | 身份及权限用例 |
| 多级返佣/外部提现 | 原生推荐政策、个人覆盖、奖励审核与转入钱包，保留原生佣金资金模型 | 账本与政策快照用例 |
| 礼品卡奖励模板 | 原生资金批次、预留、兑换、撤销与退回及对应管理页面 | 资金并发与回执用例 |
| 插件 CRUD/菜单 | 原生模块卡片、文档、配置、生命周期及声明操作控制台。现有 presentation 只声明操作 schema，没有资源表列、筛选分页映射或菜单描述，不能推断通用 CRUD | 模块所有者与运行入口用例 |
| 主题上传 | 使用 owner 提供的主题包候选及受控部署、激活、删除流程 | 主题包 gateway 用例 |
| 页面草稿/本地编辑器 | 共用 SPA 离开确认及浏览器关闭保护；本地 Worker、暗色与失败回退/重试。预取仅是有界缓存预热，仍有预取后网络失败的竞态 | 真实生产资源浏览器用例 |

上述“实现”表示源码存在，不表示测试已通过。本地只做语法、类型、边界和构建检查；功能验收按仓库规定在 GitHub Actions，且须绑定实际候选提交。提交、推送、合并和部署分别授权及记账。

# Authority finance inventory v3

Status: Candidate isolated native financial transaction admission. This fixed third inventory extends the [v2 inventory](authority-writer-inventory-expand-v2.md) on the same singleton SQL authority row. It remains legacy authority, a known-writer subset and default-off; no production cutover or global drain is claimed.

Fixed CLI `extend-finance --key=<id> --expected-epoch=2 --isolated-copy` takes the singleton exclusive lock, validates v2 legacy/open epoch2 plus all closed receipt stores, and atomically changes scope/version to `native-sql-writers/v3` / `authority-writer-fence/v3`, open epoch3, with fixed code inventory hash and one immutable finance upgrade receipt. V3 prepare accepts original expected epoch3 and commits prepared epoch4. Old v1 prepared2 and v2 prepared3 are never extended or reopened. V1 open1 must explicitly complete the original v2 expand first. Exact same key/expected-epoch replay returns the retained original upgrade receipt; changed input refuses. `recover-finance` is bounded SELECT-only and reports committed or inconclusive absence, without changing state.

The fixed inventory keeps all seven v2 writers and adds nine: `order.create`, `order.paid`, `order.fulfill`, `order.cancel`, `order.checkout`, `wallet.recharge.create`, `wallet.recharge.settle`, `commission.transfer`, `gift.redeem`. Original process config shapes stay closed: three-key config means v1, five-key scope/version config may declare the exact v1, v2 or v3 pair. Admission compares stored scope/version, fixed inventory, declared epoch and legacy role. Old workers cannot write the extended state. Read-only diagnosis validates stored histories independently of current worker declaration, within the strict local/testing isolated-copy boundary.

Only the finance upgrade receipt table is additive; authority state and prior receipt stores are retained. The new receipt binds its key, prior v2 scope/version/open epoch2, prior timestamp/hash, original v2 inventory upgrade receipt hash, fixed v3 inventory hash, expanded v3 state hash and request/content hashes. In v3, verification reconstructs the original v2 open2 state, validates the unchanged v2 upgrade receipt, then checks the finance parent receipt association. Prepared4 prior-state hash binds expanded3. Each of the three receipt stores has one bounded maximum-two-row cardinality probe. V1 null-inventory hashing and original v1/v2 prepare/upgrade recipes stay unchanged; old historical hashes are never relabelled. Missing/corrupt/extra history fails closed. DDL replay preserves data; populated down refuses.

Each nine-writer admission is the first statement of the existing outer business transaction: Order create before User; paid/open/cancel before Order; checkout before Order binding; recharge create before User and settlement before Recharge/User; commission transfer before User; gift redeem before Code/Template/redeemer/inviter. Nested UserService balance and traffic reset calls inherit their original outer SQL lock. No late first admission or process-global transaction marker is introduced, and independent calls to those helpers are not certified covered. Existing native idempotency keys, callback dedupe, Coupon reservations/refunds and queue retry paths remain authoritative.

Provider signature validation and raw provider ACK bodies stay unchanged. Only AuthorityFenceException diagnostics receive fixed nonsecret logging branches, preserving native bool/ACK/rethrow behavior. Payment provider network interactions remain outside SQL transactions and are not drained by this fence. Free checkout retains its two original transactions: prepare between committed checkout preparation and paid admission can leave the original first step committed while paid returns a conflict. This is an explicit native partial boundary, not a rollback or readiness proof. UserObserver after-commit schedule/Node effects and trusted plugin hooks remain outside global coverage.

Results report exact stored scope/version, sixteen covered writers and false `global_writer_coverage_complete`, `global_drain_complete`, `target_authority_active`, `migration_gate_open`. Financial writer admission does not invent ledger attribution, activate shadow subscription authority, migrate secrets, stop independent plugins or cover remaining registration/auth/CLI/cron/legacy traffic writers. Hash checks are consistency evidence, not signatures.

Acceptance requires actual native HTTP order create/cancel, commission and gift paths, verified synthetic payment webhook recharge/order and queued fulfillment, all admissions before domain locks, prepared refusal without partial balances/Coupon changes, native exact dedupe/idempotency, real independent transaction wait/commit/rollback/SIGKILL, finance extension/prepare output-loss recovery, old v1/v2 prepared history recovery without hash change, bounded read-only/corruption/default-off tests and full API regression. All payment adapters and data are disposable local fixtures.

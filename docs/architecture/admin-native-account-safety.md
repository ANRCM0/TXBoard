# TXBoard 主仓收尾：后台账户不可逆操作安全门禁（2026-10-09）

## 已实现

- 旧 `POST /api/v2/{secure_path}/user/destroy` 与新 `POST /txapi/admin/{admin_path}/users/{id}/delete` 统一使用 `AdminAccountProtection::deleteUnused`。仅允许删除**无资金、无套餐、无流量记录、无订单、无工单、无邀请码、无统计/重置日志、无下级用户、非 staff/admin** 的空白账户；拒绝时保留数据库记录和关联账本。带历史业务数据的账户应封禁，而非硬删除。
- 使用行锁和数据库事务防止与订单交易读取同一个用户状态时发生并发删除；原旧 Controller 的订单级联物理删除已去除。处理前/后的管理员插件 Hook 继续调用，但暂不改第三方 Hook 语义。
- Native 重置订阅 Token/UUID 复用原 Helper::guid 与插件 Hook；管理后台复制订阅链接仍为独立按需授权读取。
- Native 批量封禁限制 selected/filtered、最多 500 人、字段白名单；拒绝含管理/员工身份的选择，事务内撤销 Sanctum 登录会话。**注意**：独立 V2 批量封禁与其他老管理端尚未全面停用，仍需下一步统一入口和消费者。
- React Admin 删除、重置订阅密钥和封禁操作已迁到 `/txapi`；旧端点未直接下线。此批新增 PHP 权限、跨用户敏感字段、历史订单/金额保护、空白用户删除和前端 API 路径测试。

## 不做的事情

- 不强删历史业务账户来追求代码清理；不清除旧订单、支付回调及流量数据。
- 不碰独立 Gateway/TX-Node、真实支付商、第三方插件适配。
- CI 通过不代表部署的真实并发、插件副作用、数据库备份恢复和删除请求审计已全部验收。

## 剩余收尾

- Admin 用户新增/编辑与资金余额变更需要重新审查授权、两位小数转换、原子扣款和操作审计。
- 旧 V2 的批量封禁/群发邮件/批量生成/用户导出等需要独立迁移并对齐访问控制。
- 节点、机器、配置、支付、插件主题模块，数据库索引和真实 1Panel 备份/恢复验收尚未完成。

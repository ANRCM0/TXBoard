# Isolated local email-code send over Internal mTLS v1

Status: Current / verified isolated local slice. Fixed-source Core tests and real SDK/HPKE/Redis/mTLS/ArrayTransport checks passed; see [verification evidence](../../../docs/architecture/v2/internal-isolated-email-code-verification.json). This operation does not activate production mail, registration, password recovery or CAPTCHA providers.

`auth.email-code.send`, contract version `"1"`, uses only the existing fixed Internal mTLS boundary and `user-gateway` service identity. Its distinct `email-code` actor requires an absent Authorization header, including rejection of an empty header, and proof `actor_sha256=SHA256("")`. Native User/Admin credentials do not replace service identity. Technical audit uses actor_id `0`, not a virtual User. Global Internal enabled, local/testing environment, `core_shadow.isolated_copy=true` and the extra exact-true default-off `internal_api_slice.email_code_enabled` are all required; public/login/order flags cannot enable this operation.

The signed raw JSON envelope remains the existing closed `contract_version/request_id/deadline_at/input` object, with the 16 KiB body cap and five-second maximum deadline. Input is a required string `email` of at most 254 characters and only optional existing string `turnstile_token`, `recaptcha_v3_token`, `recaptcha_data`, each at most 4096 characters. Unknown, duplicate, missing or wrong-type fields fail transport validation. A fresh native request applies original trim/empty-to-null processing, original shared `ThrottleRequests(10,1,'')` and real `CommSendEmailVerify` validation. After normalization the recipient must have the exact case-sensitive domain `@example.test`; other recipients return `RECIPIENT_NOT_ALLOWED` 400. No caller IP, template, subject, sender, code, user ID, purpose, URL or delivery destination is accepted. Core observes the local boundary IP; this does not establish end-user IP attribution.

Execution delegates `AuthController::sendEmailCode`, `EmailVerificationService`, `SendEmailJob` and `MailService`. Before the issuer can run, a local CAPTCHA adapter requires a known disabled current SQL CAPTCHA flag, a real settings-cache array and agreement with the loaded request's CAPTCHA and email-whitelist enable/suffix policy. Cache/loaded drift or dependency failure returns `DEPENDENCY_UNAVAILABLE` 503; enabled CAPTCHA returns the native `CAPTCHA_INVALID` 400 without contacting a provider. The existing native CAPTCHA verifier runs only once that disabled policy is known. The native whitelist retains its registered-email exemption and suffix matching; synthetic recipients are still subject to that native policy.

Execution also requires current `queue.default="sync"`, the resolved exact Laravel `SyncQueue`, no current or cached after-commit dispatch, current `mail.driver="array"`, and a resolved exact real Laravel Mailer with exact `ArrayTransport`. Cached SMTP/custom transports, fake or unknown implementations and mismatched settings are refused. The operation does not swap global bindings, replace the handler, change queue/mail defaults, start a worker or contact SMTP. `MAIL_MAILER=array` alone is insufficient for the existing legacy `mail.driver` configuration.

HTTP200 success is the closed `data={ok:true}` with exact `meta={current_only:true,slice:"internal-isolated-email-code/1"}` and private/no-store headers. Code, body and recipient do not enter this response or technical audit. The existing private native MailLog still retains recipient/subject/template/config metadata; its caught send-error diagnostics follow [current mail diagnostics](../../http/mail-diagnostics-current.md). Safe dispatcher catches happen before Laravel's inner pipeline can report secret-bearing exception arguments, and the outer request/facade/guards are restored in finally. Trusted in-process listeners/plugins' own logs remain outside that guarantee.

The original cooldown/cache keys and order of work remain: atomic 60-second cooldown add, random six-digit code, synchronous Job dispatch, then a 300-second verification-code cache put. Codes retain their original shared registration/recovery semantics. Success means that this native flow returned successfully; ArrayTransport only captures a local message, not external delivery. Native ignores a false cache-put return, so success can leave a local message without a usable code. An exception after sending can clear the cooldown while leaving an emitted message. A caught send failure keeps the native Job release decision; SyncQueue does not provide a durable delayed retry. Audit failure, deadline or lost reply can hide already emitted messages and cached codes. Proof-nonce replay protection is not business idempotency; a deliberate new request can be blocked by cooldown or issue a new code. Gateway must never automatically retry or fall back after selecting this operation.

Focused gates must exercise actual local rendered message/code matching, 60/300-second cache behavior, native cooldown/whitelist/FormRequest/shared throttle, exact transport and queue rejection, settings failures/drift, request/actor restoration, nonce/service limits, safe errors and unknown side effects (false/throwing cache put, audit failure, lost/deadline response). No real SMTP, external CAPTCHA or production activation is claimed.

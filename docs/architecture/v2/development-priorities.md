# 当前开发优先级

> 更新：2026-10-16 · C1/C2 已合并 · 下一阶段：C3。
>
> 本页取代早期按 P0/P1 逐切片推进安装和迁移的排序；历史成果继续复用，不重复开发或验收。

## 当前决定

先完成 Core 的实际业务能力，再收口正式 API 与基础交付。项目仍处开发阶段，尚未接入正式测试部署，不维护旧版本过渡兼容；允许同批破坏性调整契约、真实消费者与开发 Schema，重建明确可丢弃的开发库。现存 legacy/shadow 按直接相关业务清理，不新增兼容、双写或回填门禁。

Core 继续是账户、订阅、权限、订单及结算唯一权威。Gateway、Node、Provider 不复制领域规则；身份隔离、真实 SQL 事务、持久幂等、原周期归属和秘密隔离继续生效。

## 实施顺序

| 顺序 | 阶段 | 当前状态与可验收结果 |
| --- | --- | --- |
| 已合并 | C1 购买证据 | 已购条款不可变，实际履约消费冻结输入；后续套餐修改不影响已有购买 |
| 已合并 | C2 原生订阅闭环 | 真实持久启用、免费 Offer、订阅生命周期、Provider/Node/直接渲染、有限授权与持久用量结算；限定支持范围见 [C2 runtime](../../../contracts/v2/native-c2-runtime-v1.md) |

| 2 | C4 正式接口与凭据生命周期 | 正式 Internal API、服务身份与 User/Admin 授权、生产信任/密钥轮换、长期订阅链接；Gateway 管理员接入随对应能力完成 |

C2 已完成的免费购买和用量预留不得被 C3 替换成另一套订阅/计费实现；资金事务集成现有订单、履约及 outbox。旧站自动迁移不列为 C3—C5 交付条件，未来有真实需求再立项。

## 批次与验证

连续完成一个功能或相关阶段后集中验收、修复及提交。验证围绕新增行为、权限/资金/数据库关键约束和直接受影响路径；通过后不主动追加同一矩阵。文档/CI 组织变更采用静态检查，历史迁移与扩展矩阵不作为每次 PR 的默认回归。

重型验证在 GitHub Actions 执行，本地不启动数据库、Docker、真实流量、Go race 或完整构建；大型 Linux 环境不重建。CI 调整遵守远端实际合并要求；不以未触发或跳过冒充通过，不自行绕过门禁。见[开发流程](../../development/development-workflow.md)。

新增管理和用户前端延期至独立 TX-F，仅本地提交、不推送；现有 UI/Theme 仍存在。Agent/MCP 已退役。取消过渡兼容不构成已经移除旧代码、完成新前端或发布生产版本的声明。

范围与完成条件见[完整交付计划](core-completion-plan.md)，实际状态见[当前进度](current-progress.md)。

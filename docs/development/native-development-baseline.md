# Native 开发与数据安全基线

更新：2026-10-17。项目处于开发阶段，尚未接入正式测试部署；只维护当前 native 生产者、消费者及统一插件框架，不承担旧版本、旧数据库、旧协议或旧插件包的过渡兼容。

## 当前开发规则

- Core 是账户、订阅、订单、资金、权限与用量的唯一业务权威；Provider 管秘密，Node 执行授权/计量，Gateway 适配访问。当前实现范围见[实现基线](../architecture/v2/current-progress.md)。
- 允许同批破坏性调整 Schema、API、DTO、配置与包格式；同步真实生产者、消费者、契约及针对性检查。不增加只为历史格式保留的别名、双写、shadow 或降级分支。
- 现存旧实现先核对实际依赖再清理；Xboard Node 适配器仍有实际消费者，不属于旧 Core 迁移框架。未支持入口明确拒绝，不能通过删除安全门禁冒充完成。
- 新管理/用户前端延期至独立 TX-F，仅本地提交、不推送；本仓维护 Core/Gateway/Node，唯一安装器为 TXBoard-Deploy。Agent/MCP 不恢复。
- 权限、资源归属、秘密隔离、幂等、事务、计量、持久回执及故障恢复不因取消兼容而放宽。

## 数据与重建

| 对象 | 必须遵守 |
| --- | --- |
| 来源明确且可丢弃的开发/CI 数据库 | 可针对明确目标重建，通过当前 Schema 初始化和种子建立新身份；普通启动不自动清库，不提供通用 production reset |
| 不明来源库、真实账号/资金或不可丢弃数据 | 不按开发库处理；先确认归属和保留/迁移范围，备份及验证后再操作 |
| Node spool、Provider 私有存储及 SQL 绑定夹具 | 重建整套相关夹具并重新绑定安装身份；不把旧签名、回执、秘密或未结算批次移植到新安装 |
| 历史迁移、金融/审计记录及验证 JSON | 文档清理不删除或改写；文件删除不表示运行中的表或数据已删除 |

开发库重建不等于业务回滚。旧站转换另立需求，不作为当前开发门禁。已有状态不能通过改名、改环境变量或换 epoch 伪装为新权威。

## 安装及恢复不变量

- API/Worker/Scheduler 对同一持久安装及 epoch 逐工作项准入。环境变量不能把错误模式降级，也不能代替 `initializing` 到 `open` 的持久 preflight/activate。
- 订单/订阅履约按领域契约原子提交，最终提交重验 Subject/Terms/Period 及版本；资金只认真实证据，不认用户旧余额投影。
- 已接收 native 批次按原 Period 预留；待结算/隔离均占额度，真实结算同事务释放预留并计入原周期。新周期、轮换和重启不清掉原证据。
- SQL outbox/接收/回执承担持久恢复；未知支付/Provider 结果沿原操作查询，网络调用不占用业务 SQL 事务。Node 保留原批次，禁止重贴周期或重复计费。
- 旧 Worker、失效凭据和旧备份不能使权威、高水位或撤销倒退。安装/恢复规则见[运维 Runbook](../operations/release-staging-acceptance.md)。

## CI 所有权

| 工作流 | 职责 |
| --- | --- |
| `ci-api.yml` | 当前 PHP、语法、注册路由及 Schema/权限契约审计 |
| `ci-mysql.yml` | 当前 native 初始化、事务、唯一性、并发、订阅及资金域 |
| `ci-node.yml` | Go race/vet、依赖、Node/Provider CLI 与当前镜像 |
| `ci-native-c2.yml` | native 激活、队列履约、真实 Provider、渲染、流量、轮换及原周期结算 |
| `ci-gateway.yml` | Gateway/SDK、Redis 安全、容器与浏览器 |
| `ci-web.yml` | 现存 Web 变化时的类型、测试及构建 |
| `docker-txboard.yml` | Core 镜像、Compose、依赖、启动/健康及独立正式发布资格 |
| `docs.yml` | 文档路径与 CI 策略静态检查 |

重型测试、数据库、真实服务/流量、race 和完整构建集中在 CI；本地只做语法、格式、差异及必要静态检查，不重建已删除的大型 Linux 环境。一个连贯功能批次集中验收和修复，只复测影响范围，不为更新记录重复矩阵。默认 PHP 配置覆盖当前测试；手动专项显式选择路径，不用配置别名重复默认全量。

`python scripts/check-ci-policy.py` 检查实际工作流归属、依赖和测试选择，防止退役矩阵回到自动门禁；新增业务检查放在其组件所有者。规则不替代[开发流程](development-workflow.md)及真实 required checks。

## 合并与发布

通过 Draft PR 集中 CI 验收，区分实现、精确提交已验证、已合并和已发布。失败先在 CI 修复，不绕过保护或以同名空任务冒充通过；未触发/跳过不计为通过。提交推送不自动授权自审自合、默认分支合并或镜像发布。正式标签、制品来源和恢复资格与日常 dev 镜像分开。
